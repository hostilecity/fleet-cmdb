## P2-S14: Dry-run evaluation of an unsaved rule definition

### Scope

- A service that takes a rule definition that is not saved (an edit of an existing rule, or a new rule) and evaluates it against each eligible host's latest config snapshot, using the same evaluator, applicability, and not-readable rules as [P2-S06](p2-cis-engine.md).
- Returns the hosts whose result would change, with the current result, the result under the edited rule, and the observed value. Also returns the counts the preview page shows: hosts that would change (pass to fail, fail to pass, to not applicable, and other), hosts the rule does not apply to, and hosts with no config report.
- A host that would go from a real result (pass, fail, or not readable) to not applicable is listed as a change, so the operator sees which hosts the rule would stop checking. Any other host the rule does not apply to (already not applicable, or with no result yet, as on a new rule) and a host with no config report are counted, not listed. The changes counted but not listed are counted as such, so the listed and unlisted changes together are exactly what saving records.
- The same preview serves a new rule (Add rule, then Preview, then Save): every host's current result is none, so the page shows how many hosts would pass and fail.
- A definition identical to the current version (with the same enabled flag) saves nothing, so the preview says no change.
- Validates the definition with the same checks as an import ([P2-S04](p2-cis-engine.md)) and returns the errors with their JSON Pointers instead of a preview when it is invalid.
- Writes nothing: no results, result changes, rule versions, audit entries, or jobs. It contacts no agent. It reads each host's rules, snapshot, and results without taking a lock that would block an agent report.
- Bounded: a fleet of 50 hosts and a few hundred rules previews in under 2 s; a preview is limited to one rule at a time.
- A preview is advisory. Saving evaluates the rule as it is when saved, so if the rule or a snapshot changed in between, the saved result may differ from what was shown. The preview page says so.
- Delivered as `CisDryRun.call(rule)` (`cmdb/app/services/cis_dry_run.rb`), returning `Result(errors, preview)`. `rule` is a Hash as a rule file holds one rule (the dashboard form) or a `CisRules::Definition`. It is checked by `CisRules::RuleFile.parse_rule`, the import's checks on one rule, so an invalid rule gives `errors` (`Problem(pointer, message)`, the pointer into the rule, such as `/condition/all/0`) and no preview. A stated `enabled` is honoured as an import honours it; left out, an existing rule keeps its flag and a new rule is enabled. The preview has the key, the rule id, current and next version (next is nil when the definition equals the current version, and `saves_nothing?` when the flag is also unchanged, so it lists no changes, as saving would evaluate nothing), the flag before and after, the `changes` (`Change(host_id, host_name, hostname, from, to, observed, reason, current_observed)`, by host name; `from` is nil for a new rule or a host with no result yet), and `counts` (hosts, changed, pass_to_fail, fail_to_pass, to_not_applicable, other_changes, unchanged, not_applicable, no_report, unlisted_changes). Each host in the fleet is counted once. A change from pass, fail, or not_readable to not_applicable is listed with `kind` `:to_not_applicable` (counted in `to_not_applicable`, not in `not_applicable`). A host with no config report, or that the rule would not apply to otherwise, is counted and never listed, even when its stored result would change; those are counted again in `unlisted_changes`, so the listed changes plus `unlisted_changes` are exactly the result changes saving records (a spec saves the same definition with `CisRule.define!` and `CisEvaluation` and compares). Hosts are evaluated with `CisEvaluation.outcome`, the function evaluation stores, from each host's latest snapshot (reading only the rule's fact) and its inventory's os. Six queries whatever the fleet size, none taking a lock; outside a transaction they run in one `REPEATABLE READ`, `READ ONLY` transaction, so the preview sees one committed state and cannot write. 50 hosts with 300 rules preview in about 12 ms (`spec/services/cis_dry_run_performance_spec.rb`, budget 2 s).

### Acceptance criteria

- [ ] The dry run reports exactly the result changes that saving the same definition produces, on a fleet of mixed results
- [ ] A dry run leaves every table unchanged and enqueues no job (checked by counting rows and jobs)
- [ ] An invalid definition returns its errors with JSON Pointers and no preview
- [ ] A host with no config report, and a host the rule does not apply to without dropping out of a real result, are counted and not listed as changes
- [ ] A host that would go from pass, fail, or not readable to not applicable is listed as a change
