# P2-AGENT-PACKAGES: Agent package collector (dpkg)

Implementation details for the GitHub issue with this key. The issue states only the goal and acceptance criteria; this file is the source of truth for everything else. Goal, requirement IDs, acceptance criteria, and blockers live in [`../issues.yml`](../issues.yml).

## Scope

- Detect the package manager rather than assuming one. Only `dpkg` is supported ([DEC-01](../../decisions/0001-fleet-profile.md)); a VM without it reports `unsupported` with a reason. A VM with dpkg whose packages cannot be listed reports `unreadable` with a reason (owner decision), never `unsupported`.
- Collect every installed package: name, full version including epoch and release, architecture, and source package name (dpkg's `Source` field, falling back to the package name). Use a machine-readable query format with fixed arguments.
- Send within the package report ([P2-S08](p2-packages.md)) with gzip request compression; bound the memory used for large package lists.
- Same cadence and request handling as the config report ([P2-A01](p2-agent-facts.md)).
- Fixtures from real manager output for each fleet distribution, including packages with epochs, plus-signs, tildes, and multiple architectures.
- Owner decisions on what is reported, to be implemented by the agent after the server contract (P2-S08, `packages.request`): (a) an interrupted installation (dpkg states `unpacked`, `half-installed`, `half-configured`, `triggers-awaited`, `triggers-pending`) is not reported as installed; its name and the state are sent in `skipped`. (b) A line the contract cannot carry whose package name is readable is also sent in `skipped` with a reason, in addition to the warning; a line without a readable name stays a warning. At most 64 are sent; more are one warning. The server shows a package that was installed and is now skipped as "Skipped / incomplete" in the package diff, never as removed. (c) When dpkg exists but cannot be listed (the command fails, its output cannot be read, or it is too large to send whole), `manager` is `unreadable` with the reason, no packages, and no skipped names; `unsupported` stays for no dpkg or another manager. This replaces the statements below that interrupted installations are reported as installed and that a listing that cannot be read or sent is `unsupported`. The server stores `unreadable` without losing the last known set.
- Delivered as `agent/src/packages.rs` (detection, the listing, and its parser) and `agent/src/report/packages.rs` (the reporter and the gzip body), with the `packages` type in `agent/src/report/requests.rs`; operator view in [docs/operations/agent-packages.md](../../operations/agent-packages.md). dpkg is detected by `/var/lib/dpkg/status`; without it the reason names `rpm` or `apk` if found. The listing is one fixed command through the `Host` trait, `/usr/bin/dpkg-query --show` with five tab-separated fields (`${db:Status-Status}`, `${Package}`, `${Architecture}`, `${Version}`, `${source:Package}`, which is the `Source` field without its version, or the package name). Installed means what apt counts as installed: every status but `config-files` and `not-installed`, so held packages and interrupted installations (`unpacked`, `half-configured`, `half-installed`) are reported; the AC-2.3 reference listing is `dpkg-query --show` without the `config-files` lines. A line the contract cannot carry is skipped with a warning (a bad source name is sent as `null` with one), never cut; a listing that cannot be read, or is too large to send whole (over 20,000 packages, 4,000,000 bytes of JSON, or 1,000,000 compressed), is sent as `unsupported` with the reason rather than in part. The cadence is the config report's, with no setting of its own (`[config_report] interval_seconds`): startup, schedule, and one report per `report_request` episode naming `packages`. The body is serialized straight into a gzip encoder (`flate2`, pure-Rust backend) and only the compressed bytes are kept for a retry; peak heap for a 3,000-package listing is about 1.0 MB (1,018,534 bytes measured; 1,038,384 with the real `dpkg-query`). Stopping takes at most the listing (20 s) or one request (30 s), inside the 40 s the inventory loop already takes. Fixtures: `agent/tests/fixtures/packages/debian13/`, a modelled Debian 13 `status` file and the real `dpkg-query` output for it (a test re-runs `dpkg-query` to check). AC-2.3 is checked against the dpkg database of the machine running the tests and, on a Debian 13 VM under the real unit, by `agent/scripts/vm-test.sh` (scenario 300); `agent/scripts/sandbox-smoke.sh` checks the sandbox costs no package.

## Acceptance criteria

- [ ] The reported set equals the output of the VM's own package listing, with no packages missing or invented (AC-2.3 check)
- [ ] Source package names are present where the manager records them
- [ ] An unsupported manager is reported explicitly
- [ ] An interrupted installation is reported as skipped, not installed, and a dpkg that cannot be listed is reported as `unreadable`
- [ ] Peak memory on a 3,000-package host stays modest (measured and noted)
