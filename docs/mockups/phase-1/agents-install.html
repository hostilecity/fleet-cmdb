Install an agent

Current release 0.2.0, signed and verified. Needs Debian 13 on x86_64 with systemd, root, and HTTPS access to agent.fleet.example.lan.

One VM, approved hereUnattended

  1. Download the agent

    On the VM:

    curl -fL -o fleet-agent https://agent.fleet.example.lan/api/v1/releases/0.2.0/binary

  2. Check it

    echo "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef fleet-agent" | sha256sum -c

    It must print fleet-agent: OK. If it does not, do not run it.

  3. Run the installer

    chmod +x fleet-agent && sudo ./fleet-agent install --server https://agent.fleet.example.lan

    It checks the VM, installs the agent, and prints a link and a code like WDJB-MJHT.

  4. Approve it here

    Open the link, or go to Awaiting approval. Check that the code matches the terminal, name the host, and approve. The installer finishes by itself within a few seconds.

Unattended: cloud-init, templates, scripts

No one is there to approve, so pre-register the host first. You get a one-time token, valid for 24 hours, and the installer uses it instead of an approval.

#cloud-config runcmd: - curl -fL -o /root/fleet-agent https://agent.fleet.example.lan/api/v1/releases/0.2.0/binary - echo "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef /root/fleet-agent" | sha256sum -c - chmod +x /root/fleet-agent - FLEET_ENROLLMENT_TOKEN='EXAMPLE-enrollment-token-not-a-real-one-0001' /root/fleet-agent install --server https://agent.fleet.example.lan --quiet

The token works once. A template that clones many VMs needs one pre-registration per VM.

Afterwards

Agents update themselves when you run a rollout on the Agents page, and roll back by themselves if an update fails. To upgrade one VM by hand, run the installer from a newer release; it keeps the credential.

The download URL, checksum, and version always come from the release the page shows, so a copied command never mixes releases (P1-D08). The installer prints a QR code of the link under it, for approving from a phone.
