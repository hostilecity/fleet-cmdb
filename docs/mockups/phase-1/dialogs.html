Confirmations

Destructive actions ask first (FR-S.4). Shown here open; in the app each opens over the host page.

Revoke the credential for Media server?

The agent on vm-01.example.lan is refused from its next request and the host stops reporting. To let it back in, re-enroll it.

Re-enroll Media server

Use this when the VM lost its credential, was rebuilt, or was revoked. Choose how the VM gets its new credential:

Approve from the VM (recommended). On vm-01.example.lan, as root, run fleet-agent install --reenroll. Approve the request that appears, choosing "Re-enroll Media server". Nothing changes until you approve.

Issue a one-time token for an unattended reinstall. The host moves to pending now; its current credential keeps working until the token is used. Any earlier unused token stops working.

Retire Media server?

Retiring revokes the credential and removes the host from the fleet list and counts. Its inventory, history, and audit entries are kept. This cannot be undone.

Halt the rollout to 0.2.0?

No more hosts are offered 0.2.0. Hosts already updating finish, and roll back by themselves if they fail. You can resume later.

Start rolling out 0.2.0?

2 canary hosts (tag canary) update first. The next stage starts only when every canary confirms; any failure or rollback halts the rollout.

Retire asks for the hostname because it is the only action that cannot be undone. Revoke and re-enroll can be reversed by re-enrolling, so a single button is enough.
