Confirmations

Phase 2 actions that change what the fleet shows. Shown here open; in the app each opens over the page it came from.

Disable ssh-max-auth-tries?

The rule is no longer evaluated. Its result on all 5 hosts becomes "Not evaluated", and it drops out of every host's pass rate until you enable it again. Fleet failure counts fall by 2 (Media server, Web A). Its history and versions are kept.

Enable ssh-strong-ciphers?

Every host's latest config snapshot is checked against it now. No agent is contacted. Pass rates and failure counts change when the checks finish, within a minute.

Refresh advisory data now?

Downloads the configured feed (feeds.example.lan/osv/Debian/all.zip) and imports it. This can take several minutes. Findings are matched again afterwards for the packages that changed. It is also the scheduled job, so running it now does not skip the next one. Debian's triage data (the Debian Security Tracker) is refreshed right after it; if that fails, the advisory data is still imported.

Import as a full import?

A full import treats the file as the complete advisory list for its ecosystem. Advisories it does not contain are marked withdrawn, and findings that depended on them resolve as withdrawn. Use it only for a complete download, not for a few records.

Disable names its effect in numbers because disabling quietly improves every pass rate. Enable and refresh are one button each: both can be reversed or repeated. Full import gets a confirmation because it can resolve findings.
