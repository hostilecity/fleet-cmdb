P2-D07 review. The Debian Security Tracker is a second source panel below the advisory data, marked "Triage only" so it is not read as a second source of findings. It has its own freshness, release table, and imports, and no upload. Drawn: it shares the advisory schedule (it runs right after the OSV refresh, as the spec says) and shares the one "Refresh now" button and its cool-down (T2). If that is chosen, the refresh confirmation (Confirmations) gains one sentence: "Debian's triage data is refreshed right after it." Entry counts are per release and only for releases the fleet uses. A held-back import is a row here with its counts, and the page shows a notice while it is the latest (held-back state); the stale state is on the stale page.

Decided in the P2-D01 review (Q14): manual refresh has a cool-down of 5 minutes, like report requests. The button is greyed out with the time left, so no alert is needed after a click. "Refresh now" and the upload form sit beside the scheduled feed, each with a confirmation where it can resolve findings (Confirmations). The feed itself can only be changed in the server configuration, since it carries a token.
