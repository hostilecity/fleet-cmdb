The cancel confirmation in each case. Shown here open; in the app each opens over the task or batch page. Each needs the second factor unless it was passed in the last 5 minutes.

Cancel task #1208 on sim-028?

Cancel task #1214 on sim-031?

Stop task #1212 on sim-012?

Collecting reports can be stopped safely. The agent gets the cancel on its next poll, within about 30 seconds, and stops. Reports it has already sent are kept. The task ends as cancelled.

Task #1207 on sim-027 cannot be stopped

It will keep running until it finishes, at 15:05:40 UTC at the latest. Applying package updates cannot be stopped safely once started: stopping the package manager part-way can damage the package database.

What you can do: record that you asked to cancel, and stop the 1 task in batch 87 that has not started (sim-028) from ever starting.

It will keep running until it finishes, at 23:10:00 UTC at the latest. Applying package updates cannot be stopped safely once started. It is not part of a batch, so there is nothing else to stop.

Cancel the rest of batch 87?

  • 1 waiting task (sim-028) becomes cancelled now and is never delivered.

  • 6 finished tasks are not changed. Nothing is undone.

Review Q23. The cancel button is labelled by what it can do: "Cancel task" for queued and claimed, "Stop task" for a running task that can be interrupted, and "Request cancel" on the page for one that cannot, which opens a dialog whose title says it cannot be stopped. The batch dialog counts what will and will not change. "Nothing is undone" is said outright, because a cancel never rolls back a finished restart or upgrade. Any operator can cancel any task, not only the one who created it. Alternative: only the creator and the owner can cancel. The dialog for a lone non-interruptible task still offers to record the request, for the audit trail; say if it should only explain and close.
