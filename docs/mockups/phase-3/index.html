Each is also a review note on the page named after it. The owner answered them on 2026-11-08: every drawn choice is accepted, except where the decision below says otherwise.

  1. Q1. "Tasks" in the top bar second, after Fleet. Alternative: next to Agents. tasks.html Decided: As drawn.
  2. Q2. The Tasks list is one row per task, opening on All, newest first, with state chips. Alternative: open on the problem states. tasks.html Decided: As drawn.
  3. Q3. The create flow as four short pages with no JavaScript. Alternative: one long page. create-type.html Decided: As drawn.
  4. Q4. Plain names first ("Restart a service") with the type id small beside them. Alternative: type ids only. create-type.html Decided: As drawn.
  5. Q5. The service is chosen from a list of every allowlisted service, with its tag named; hosts outside the tag are left out at the targets step. Alternative: targets first, then only services allowed on all of them. create-params.html Decided: As drawn.
  6. Q6. The Phase 2 "Request fresh report" buttons stay (no second factor); the Collect fresh reports task, which needs one, is for batches. Alternative: replace the buttons with the task. create-params.html Decided: As drawn.
  7. Q7. The server cannot see each VM's own service allowlist, so those VMs refuse at run time. Recommended alternative (a P3-A01 change): agents report their local allowlist so those hosts are left out before anything is sent. create-targets.html Decided: Agents report their local allowlist; hosts that do not allow the service are left out at the targets step.

Wording and data

  • Every task is named by what it does, in the catalog's words, never as a command. No page has a field whose value is sent to an agent as a command; the only typed name in Phase 3 is a service added to the allowlist, checked against a strict pattern.
  • The fixed programs on the confirmation are labelled as built into the agent and not sent by the server, with the exact payload the server sends beside them.
  • Hosts are sim-0NN.example.lan, operators are example.operator@example.com and example.reviewer@example.com, the package mirror is deb.example.lan, and every key and recovery code contains EXAMPLE or EXMPL. The QR code is random and encodes nothing.
  • No JavaScript and no external requests. Fonts are the system stack, as in Phase 2.
  • Accessibility: every state is a word as well as a lamp shape, every table has headers, form fields have labels, errors are announced and shown beside the field, and every page works at phone width.
