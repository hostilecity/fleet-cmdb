There is no service you can restart.

The server's allowlist of restartable services is empty, which is how it starts (ADR 0015). Add a service in Settings: Tasks, then add the same service to each VM's own allowlist in /etc/fleet-agent/config.toml. Until both list it, a restart is refused.

No host will run "Apply package updates".

It is off by default on every VM, and none of the 41 active hosts has turned it on. To allow it on a VM, add apply_package_updates to [tasks] enabled in that VM's /etc/fleet-agent/config.toml and restart the agent; the host reports it within a minute. This cannot be turned on from the dashboard.

A request that did not come from this form

The server applies every rule on every request, not only in the form: an unknown type, a parameter outside its schema, an extra field such as command, a service not on the allowlist, more than 25 hosts, a missing typed count above 3 hosts, or a missing or old second factor. Each is refused before anything is stored, with the same message the form would show, and recorded in the audit log as a refused creation (Audit log).
