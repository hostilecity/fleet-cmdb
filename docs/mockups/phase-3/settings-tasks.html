LivenessTasksYour second factor

Services that can be restarted

The "Restart a service" task offers only these. Each VM must also list the service in its own configuration ([tasks] allowed_services in /etc/fleet-agent/config.toml); a restart runs only where both lists have it.

A systemd service unit name as systemctl shows it, ending in .service: lower-case letters, digits, and - _ ., up to 64 characters. Instances such as getty@tty1.service are not accepted.

Review Q31. The allowlist takes a typed name, the one free-text field anywhere in Phase 3, because services must be named somewhere (ADR 0015). It only ever becomes an entry in this list, checked against the pattern above; the restart task then chooses from the list. Drawn: full unit names ending in .service, no template instances (@), each entry for every host or for one tag. Alternatives: allow names without the suffix and add it, or allow several tags per entry.

Fixed in the server and the agent (ADR 0015). Adding one of these to the list above is refused, and the agent refuses it even if a VM lists it.

Q32, decided (owner, 2026-11-08). As ADR 0015: protected services are always refused, even if listed, with no override anywhere. Restarting SSH or the agent is a job for the console. FR-3.1 and P3-A06 now say the same.

Review Q33. The ranges are proposals: batch size 1 to 25 (it can be lowered, never raised past the cap); output 4 KiB to 1 MiB; poll hint 10 to 300 seconds; expiry 1 hour to 7 days per type. FR-3.2 makes expiry configurable per type and sets only the 24-hour default. Changes apply to tasks created afterwards; tasks already queued keep the expiry they were created with. Adding or removing a service asks for the code in the same way (drawn below).
