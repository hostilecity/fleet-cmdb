What the agent does on each of the 7 hosts

  1. Checks the task itself: restart_service is enabled in the VM's configuration, nginx.service is in the VM's own allowlist, and it is not a protected service. If any check fails, it refuses the task and runs nothing.
  2. Asks systemd to restart nginx.service. The service stops and starts again; connections it is serving are dropped.
  3. Checks that nginx.service is running again, then reports Succeeded, or Failed with systemd's output.

It does not restart any other service, change any file, or reboot. It stops after 5 minutes at most. Once started it cannot be cancelled: stopping a restart half-way could leave the service down.

The exact programs the agent runs (fixed in the agent, not sent by the server) 
/usr/bin/systemctl restart -- nginx.service
/usr/bin/systemctl is-active -- nginx.service

Built into agent 0.9.0, catalog version 1. The server sends each agent only the task type and the parameter, which the agent checks again before using:

Apply package updates on 3 hosts

ParametersNoneAlways the same (ADR 0016)
Hosts3sim-021, sim-022, sim-023

What the agent does on each of the 3 hosts

  1. Checks that apply_package_updates is enabled in the VM's configuration. If not, it refuses and runs nothing.
  2. Refreshes the package lists from the VM's configured Debian sources.
  3. Upgrades installed packages to their newest versions. Packages on hold are not touched. An upgrade that would remove a package or install a new one is held back and listed. Changed configuration files keep the local version. If another program holds the package manager, it waits up to 5 minutes, then fails without changing anything.
  4. Reports which packages were upgraded and held back, whether a reboot is needed, and which services use old libraries, then sends a fresh package report.

It does not reboot, restart services, remove packages, or change the Debian release. It stops after 60 minutes at most; if it is stopped then, the package database may need repair (dpkg --configure -a), and the task says so. Once started it cannot be cancelled: stopping the package manager part-way can damage the package database.

The exact programs the agent runs (fixed in the agent, not sent by the server) 
/usr/bin/apt-get update
/usr/bin/apt-get upgrade --yes -o DPkg::Lock::Timeout=300 \
  -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold
/usr/sbin/needrestart -b
Environment: DEBIAN_FRONTEND=noninteractive, LANG=C, a fixed PATH; nothing else.
Reboot needed: from needrestart's kernel and library status.

The server sends only {"type": "apply_package_updates", "params": {}}. The lines above are the draft from ADR 0016; P3-AGENT-UPDATES fixes the final ones and this box will show exactly those.
