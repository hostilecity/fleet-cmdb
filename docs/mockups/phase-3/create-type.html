Review Q3. The flow is four short pages (type, parameters, targets, confirm), each a plain form with Back links and no JavaScript, so every step works the same at phone width and the server re-checks each step. "Read what exactly it will do" is the description on this page and again, in full, on the confirmation. Alternative: one long page with all four sections. The descriptions are the catalog's own text (P3-S01), so the dashboard can never say something the agent does not do. "Hosts that will run it" counts active hosts whose agent reports the type as supported and enabled.

Review Q4. Plain names first ("Restart a service") with the type id beside them in small monospace. Alternative: type ids only, which match the catalog and the audit log but read like code.
